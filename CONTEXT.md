# Indulge CRM — Project Context

_Last updated: Oct 8, 2026 (PT). This file is for other tools and AIs. It contains **no secrets**. Never add passwords, API keys, tokens, password hashes, or the page key to this repo, because it is **public**._

## 1. What it is, who it's for, what it solves

**Indulge CRM** (the "Ai Sales Manager" app, v1.1) is the internal sales CRM and analytics app for **Indulge Distributions**, a licensed Oregon cannabis wholesale distributor. Its brands include Ripped City and Legends. It is used by:

- **Sales reps:** accounts, deals, visits, routes, coaching, and their own numbers.
- **Management/admin:** team performance, leaderboards, forecasting, and fulfillment.
- **Ops/fulfillment:** open orders, ship dates, routes, and delivery calendar.

**Problems it solves**

- **One place for the sales data.** LeafLink order history from 2018 to today is otherwise spread across LeafLink, CSV exports, HubSpot and spreadsheets. Here it is cleaned, normalized and searchable in a single place.
- **Fast questions about the book.** Year-over-year and period comparisons, product-line, brand and category mix, rep and account leaderboards, and new and lost accounts.
- **Day-to-day rep work.** Account status, assignment and reassignment, deals, notes and next contacts, visit scheduling, route planning, and a delivery calendar.
- **AI help.** "Clarence" is an AI assistant that runs reports over all the data and highlights whatever the user is currently filtering.
- **Safety.** It is read-only toward LeafLink and Metrc for now (see Phases).

## 2. Tech stack

| Layer | What |
|---|---|
| Front end | A **single static HTML file** with vanilla JavaScript and CSS. There is no framework or bundler; the page is generated by Python build scripts. Charts and maps are hand-rolled SVG/canvas inside the page. It must work at 390px wide (phones) and in Safari/WebKit. |
| Page protection | The whole page body is **AES-256-GCM encrypted** (`"v":2` payload). The public `index.html` is only an unlock shell. The user signs in with a per-user account against the crm-sync Worker (`/auth/login`), and only a valid session receives the page key (`/auth/page-key`) to decrypt the page in the browser. Plaintext is never published. |
| Hosting | **GitHub Pages** from this repo (`main`, root, `.nojekyll`): https://ethangilman-hash.github.io/ai-sales-manager-v1/. There is also a **Cloudflare Pages mirror** with byte-identical files: https://ai-sales-manager-v1.pages.dev/ (`wrangler pages deploy`). |
| Backend | The **`crm-sync` Cloudflare Worker** (TypeScript), a separate **private** repo: `ethangilman-hash/crm-sync`, live at https://crm-sync.ethangilman.workers.dev. It handles auth (JWT sessions, salted password hashes), the page-key release, shared CRM records, a read-only LeafLink proxy, the Clarence AI endpoint, Gmail send/tracking, and route stops/overrides. |
| Database | **Cloudflare D1** (SQLite), database `crm-sync`. The sales history itself is **not** in D1; it is embedded (encrypted) in the page. |
| Data pipeline | Python 3 (pandas) on the build machine: `leaflink/pull.py` (incremental **read-only** LeafLink API v2 pull, GET only) → merge with historical CSV base → `yoy_dashboard/build.py` → `encrypt_page.py` → commit `index.html` here → mirror to Cloudflare. |
| AI | The Clarence chat runs through the Worker's `/ai/chat` (OpenAI-compatible chat model configured in `wrangler.toml` vars, with a fallback model and a daily per-user limit). Its tools are executed **client-side** against the decrypted in-page data (`AIC.T.*`). Tool schemas live in `crm-sync/src/ai_tools.ts`, and the system prompt in `src/ai.ts`. |
| External | **LeafLink** API v2 (orders, customers, products, staff; read-only). **HubSpot** export (activity history). **Google OAuth/Gmail** (send and open tracking, plus a Chrome extension in crm-sync). Emerald Triangle inventory scrape. Geocoding (ZCTA) for maps and routes. **Metrc** is not integrated yet. |
| Testing | Playwright (Chromium/Chrome and WebKit) screenshot and smoke scripts; `node new Function` syntax checks; `ops_work/totals.py` checks that totals are unchanged; and `live_verify.py`, which byte-checks both live sites, confirms there is no plaintext, key or password in the page, and checks totals. |

## 4. Data models and data flow

### Data flow

```
LeafLink API v2 (GET only) ──► leaflink/pull.py ──► merge with historical CSV base (clean_csv_base.pkl)
   orders/customers/products/staff        │            → clean.pkl  (~83.8k paid line items, Apr 3 2018 → today)
                                          ▼
HubSpot export, CRM export, Emerald inventory, geocodes ─► yoy_dashboard prep/build scripts
                                          ▼
                       index_plain.html (never published) ─► encrypt_page.py (AES-256-GCM)
                                          ▼
               pages-yoy/index.html ─► git push (GitHub Pages) ─► wrangler pages deploy (Cloudflare mirror)

Browser: unlock shell ─► crm-sync /auth/login ─► /auth/page-key ─► decrypt ─► SPA runs fully client-side
         SPA ⇄ crm-sync (D1) for shared CRM records, routes, notes, email tracking, Clarence /ai/chat
```

### Embedded (in-page) data

- **Line items:** order number, date, account/parent, rep, product, product line, brand, category, units, sales $, zone/geo. These are paid wholesale lines (Accepted/Fulfilled/Shipped/Complete). Samples and internal/wholesale buyers (e.g. Indulge Circular, internal transfers) are excluded from Sales Data.
- **CRM account packs:** status, assigned rep, parent account, license, contact info (encrypted with the page).
- **Inventory:** LeafLink on-hand minus reserved.
- **Open orders and fulfillment snapshot:** status, ship date, payment terms, backorders.
- **Map, geo and HubSpot activity.**

### D1 tables (crm-sync)

| Table | Purpose |
|---|---|
| `reps` | User accounts: username, display name, LeafLink staff id, `is_admin`, salted password hash (never plaintext). |
| `sessions` | JWT session ids and expiry |
| `deals`, `visits`, `goals`, `activities` | Shared CRM records. JSON payload, `updated_at`/`updated_by`, soft delete, last-write-wins. These are generic collections at `/<collection>`. |
| `notes`, `next_contacts` | Account notes and next-contact dates |
| `parent_overrides` | Manual parent-account mapping |
| `route_stops`, `route_overrides` | Route planning, multi-day routes, arrival dates, reassignment overrides |
| `email_events`, `email_opens`, `google_oauth_tokens` | Gmail send and open tracking |

| `audit_log`, `meta` | Audit trail and key/value metadata |

## 5. Status (as of Oct 8, 2026)

### Built and working

- **Per-user login via crm-sync.** Individual rep accounts with hashed passwords, JWT sessions and password change. The page key is released only to signed-in users. Rep password changes are live, and old passwords no longer work.
- **Encrypted publishing to two sites.** GitHub Pages and the Cloudflare mirror are byte-checked after each publish. No plaintext, key or password is in the page.
- **LeafLink read-only pull.** `pull.py` runs on a schedule **every ~2 hours on weekdays** (e.g. 12:58 and 2:58 PT). It merges new live orders, refreshes inventory, open orders and rep diffs, rebuilds, encrypts and publishes. `WRITES_ENABLED=false`: there are no LeafLink writes.
- **Sales Data and Customer Leaderboard.** Monthly and YoY trends, product line, brand and category mix, pies, heat map, top products, CSV download, rep, zone, account and channel filters.
- **Multi-year + date-window filters (new Oct 8).**
  - Years is a multi-select. Dates are All / MTD / YTD / QTD / Last 7, 30, 60, 90 / Last year / Custom.
  - Combining them, e.g. **Last 60 + 2024 + 2025**, applies the *same calendar window in each selected year*. A "same dates, year over year" comparison card shows each year and the change vs the year before. Feb 29 becomes Feb 28 in non-leap years.
  - Dates All gives full years; Years All gives the plain latest window. The URL hash keeps both.
  - All totals, cards, pies, heat map, fun facts, tables and Clarence follow the combination.
- **Clarence with all-data access (new Oct 8).** It answers from the whole dataset by default. When the user has filters on, it adds an "In your filter (…)" highlight with in-filter totals and per-row ● markers. It can apply filters, including period × years.
- **Account reassignment.** Rep reassignment with overrides synced through crm-sync.
- **Routing and calendar.** Multi-day routes with arrival dates, a Sunday-first calendar, and "Add to route".
- **Fun facts.** A rotating, filter-aware fun-fact banner.
- **Planning and fulfillment.** Open orders, ship-today/overdue counts, backorders, and payment terms.
- **Other.** Menu & Inventory, Accounts/Deals/Activity (HubSpot history), maps, Gmail send/open tracking (extension + OAuth), and the Ai Sales Manager tab (coaching KPIs, plan CSV, print).

## Working rules for contributors and agents

- **Never commit or print secrets.** That covers passwords, hashes, API keys, the JWT secret and `PAGE_KEY`. This repo is public, and its content must stay encrypted.
- **Publish only via `leaflink/pull.py`.** Use `--skip-fetch` when a fresh LeafLink pull isn't needed. Run `pgrep -f leaflink/pull.py` first and wait if a pull is running. Don't collide with the scheduled pulls (~:58 every 2 hours on weekdays).
- **Before every publish:**
  - make backups;
  - check that totals are unchanged by UI-only changes;
  - check the page at 390px and in WebKit/Safari;
  - byte-check both live sites.
- **Keep `WRITES_ENABLED="false"`.** Make no Metrc writes until the corresponding phase is approved.
- **When crm-sync changes,** run `npx tsc --noEmit -p .`, then `npx wrangler deploy`, then commit and push the crm-sync repo.
